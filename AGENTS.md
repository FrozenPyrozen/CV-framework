# AGENTS.md

Entry point for any AI agent working in this repo (Claude Code, Codex, Cursor, Gemini CLI …). Read this file first, then the agent definition for your task in `agents/`.

## What this repo is

A local, specification-driven framework that keeps Kirill Kohan's CV current, traceable and ready to send:

- **Sources:** work summaries (`summaries/*.md`, one per job or project), confirmed facts and decisions (`facts/`), role profiles (`profiles/`), markets (`markets/`), templates (`templates/`), `framework.config.yaml`.
- **Outputs:** the master CV (`cv/<Name>_CV.md`), role variants (`cv/variants/<profile>/cv.md`), job-specific CVs (`cv/tailored/<company-role>/cv.md`), and their Word, PDF and preview files for every market.
- **Deterministic work is done by scripts** (`npm run …`). **AI agents only write and judge**, following the specs.

The full design is in `docs/plan.md`. The rules are in `specs/`.

## Rules for every agent

1. **Specs first.** Follow the specs in `specs/` (`cv-spec.md`, `work-summary-spec.md`, `facts-spec.md`, `tailoring-spec.md`, `templates.md`, `review-report-spec.md`, `portability-spec.md`, `sources-spec.md`, `outputs/portfolio.md`, `outputs/cover-letter.md`) and the rubrics in `specs/rubrics/`; read the sections your agent's *Read first* list names (and a spec's *Rules at a glance*), opening others only when a step points there. If a spec and a request conflict, say so and ask; don't silently deviate.
2. **Every claim needs a source.** Never write a CV claim without a summary contribution, summary section or confirmed fact behind it. If the user wants something unsourced in the CV, it becomes a confirmed fact first (`/add-experience`).
3. **Never invent.** Unknowns are `TODO (needs user input)` in summaries, or a question to the user. No invented numbers, dates, titles or technologies.
4. **The user's manual edits are kept.** Start from files as they are on disk. Edit CVs one entry at a time and run `npm run reattach-src -- <file> --save` before the first edit.
5. **Never commit.** Leave changes uncommitted, show a diff and a short change log. The user reviews and commits.
6. **Every AI step ends with a deterministic check.** After a change: `npm run verify -- --fast` while iterating, `npm run verify` before handing back. After editing a CV, run `npm run reattach-src -- <file>` first; `npm run build -- <file>` builds one CV. Report failures; don't hide them.
7. **Confidentiality.** The repo is local or on a private remote only. Summaries describe work in your own words: no source code, copied internal documents, internal URLs or secrets. Terms in a summary's *Confidentiality notes* never appear in a CV (lint enforces it).
8. **Employment type is a fact.** `engagement` records the real employment type; "(Contract)" appears only when it's true (decision `all-full-time`).
9. **Decisions in `facts/decisions.yaml` are settled.** Follow them; reviewers list matching findings as *Decided*.
10. **US English.** Plain words for a mixed audience; no filler words (`checks.filler_words`).
11. **Don't use `cns:*` skills in this repo.** They belong to a different project.
12. **Ask the user** for job details, numbers, employment types, new tags, approvals and anything only they can know. Ask one topic at a time, with suggested answers.
13. **Specs name config keys, not their values** (`checks.max_words`, not its number); `npm run doc-check` catches copied values that drifted, plus unknown scripts, flags, paths and section numbers.

### Agents (`agents/`)

- `agents/advisor.md`: Talks with the user, one topic at a time, to turn review findings, new experience, profile changes and job changes into confirmed facts, decisions and summary updates, then hands the changes to the composer.
- `agents/composer.md`: Updates the master CV from the summaries and confirmed facts, one entry at a time, keeping the user's wording and every source comment.
- `agents/cover-letter.md`: Writes a cover letter for one job ad (cv/tailored/<company-role>/cover-letter.md) from the same sources as its tailored CV, with a source on every sentence; a script writes the header, checks and builds it.
- `agents/harvester.md`: Writes or merges a work summary (summaries/<id>.md) from a local git repo, asking the user for everything git can't know.
- `agents/portfolio.md`: Writes the public portfolio's text (portfolio/portfolio.md) from the opted-in summaries, one project at a time, with a source on every sentence; the scripts write everything else.
- `agents/reviewer.md`: Reviews a CV against one rubric and writes a report; never edits anything. Run once per rubric (ats, hr, proofreading, fact-check, confidentiality, layout).
- `agents/tailor.md`: Builds a role variant (cv/variants/<profile>/) or a job-specific CV (cv/tailored/<company-role>/) with a gap report; a script selects the bullets, the agent words them.
- `agents/template-importer.md`: Turns a Word CV into a reusable template (templates/<name>/) by labeling its paragraph types, then test-builds the user's CV with it for approval.
